TL;DR — Unlike traditional UI testing agents that execute predefined tasks, UIFlowCrawler systematically explores every UI state in your macOS app. A Python advisor algorithm (not the LLM) controls exploration order, guaranteeing completeness. The LLM only decides how to execute each action. The result: a complete state transition graph, optimized test flows, and production-ready BDD Gherkin test cases — all fully automated.
The Problem

Why existing approaches fall short

Manual E2E testing is slow and incomplete. LLM-based agents are creative but unreliable for systematic coverage. UIFlowCrawler combines the best of both worlds.

⚙

Manual Testing

Testers follow predefined scripts. Coverage depends on what they think to test. Unknown states remain undiscovered.

❖

LLM-Only Agents

LLMs choose what to explore next. They get stuck in loops, miss branches, and have no completeness guarantee.

✓

UIFlowCrawler

Algorithm decides what to explore. LLM decides how to act. Code enforces loop prevention and coverage tracking.

Architecture

How it all connects

Claude Code orchestrates exploration through Appium MCP while the Python advisor controls strategy.

Skill Prompts

.claude/commands/ define the exploration and generation workflows as structured prompts for Claude Code.

Appium MCP Server

Provides UI automation tools (click, type, get page source) as MCP functions the LLM can call directly.

Python Scripts

advisor.py, normalize.py, and report.py handle algorithmic logic, state fingerprinting, and report generation.

Three-Phase Pipeline

From app launch to test cases

Each phase has a distinct goal and produces concrete artifacts.

01

Explore

Advisor-guided state discovery. The LLM interacts with the app while the algorithm ensures every reachable state and action is visited.

  • MD5 fingerprinting of accessibility trees
  • Greedy selection of unexplored (state, action) pairs
  • Code-level visited set prevents loops
  • Outputs: utg.json, per-state screenshots and element data
02

Design

Graph algorithms generate optimal test flows covering all discovered state transitions with minimal redundancy.

  • Flow generation from state transition graph
  • Grouped by feature area
  • Covers all edges in the transition graph
  • Outputs: flows.json with grouped test flows
03

Generate

BDD Gherkin test cases with separated Generator and Evaluator LLM calls to prevent self-serving bias.

  • Happy path, error, and boundary scenarios
  • Generator writes, Evaluator reviews independently
  • Uses actual UI tree data for realistic steps
  • Outputs: .feature files + interactive HTML report

Quick Start

Up and running in minutes

Prerequisites: macOS, Node.js, Python, and Claude Code CLI.

1

Install dependencies

# Install Appium and the macOS driver npm install -g appium appium driver install mac2 # Install Python dependencies pip install -r e2e-coverage/requirements.txt
2

Configure your target app

# Edit e2e-coverage/conf/appium_mac.json # Set the bundleId to your target macOS app { "bundleId": "com.apple.weather" }
3

Run exploration

# In Claude Code, use the slash command: /e2e-coverage > Explore the Weather app (com.apple.weather)
4

Generate BDD test cases

# After exploration completes: /bdd-gen # Output: e2e_output/features/*.feature + report.html
Output

What you get

Everything is saved to a single output directory with a rich interactive HTML report.

e2e_output/ ├── states/ # Per-state screenshots + element data ├── utg.json # State transition graph ├── flows.json # LLM-designed test flows (grouped) ├── features/ # BDD Gherkin .feature files └── report.html # Interactive HTML report
